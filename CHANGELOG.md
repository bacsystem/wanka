### Added
- `apps/web`: the `/login` screen and its BFF (story #24, frontend part; stacked on #251). `POST /api/auth/login` (open in `OPEN_API_ROUTES`) calls `POST /v1/auth/login` with `X-Client-Ip`, checks the origin (CSRF) and the body, and keeps the tokens only in `httpOnly` cookies (`SameSite=Lax`, `Secure` in production builds): `wk_at`, `wk_rt` and `wk_at_exp` (all `Path=/`, as ADR 0004 and conventions §2 say, so `proxy.ts` can refresh in #234), plus `wk_ch` / `wk_en` (`Path=/api/auth`) for the two-step pending states (#25); a login that does not open a session clears the cookies of a previous state. The request body is capped at 4096 bytes counted while it streams (`413`), and `experimental.proxyClientMaxBodySize` is `1mb`. The browser only gets `{status}` or `{code, retryAfterSeconds}`; `401` is one generic message, `403` says the account has no company, `429` and `503` honor `Retry-After` and keep the button disabled until it passes. `mfa_required` shows a «verificación en dos pasos, próximamente» screen. ## [0.19.0] - 2026-11-19

### Added
- `apps/api`: the permission step of the `/v1` route chain (`auth.Routes.Handle`, story #176), mounted by the router after entitlements and before the route's own steps and idempotency, so no module can drop or move it. A `Tenant` route now needs a catalog permission (`Spec.Permission`, checked at startup against `internal/platform/permission`; `NoPermission` only on `Public`, `NoTenant` and `GET /v1/me/entitlements`; a `plataforma.*` code or an unknown one aborts the start). Per request, in order: if the session's `authz_version` differs from the membership's (or is NULL) the role is re-resolved and the session is updated with `UPDATE ... WHERE id AND membership_id AND revoked_at IS NULL` (`SessionResolver.BindVersion`; 0 rows is `403 tenant_access_denied`, nothing cached); a role with `requires_mfa` on a session with `mfa_method = none` revokes the session and answers `403 mfa_required`; a missing permission answers `403 forbidden` with `permission` and is recorded with `audit.RecordDenied` (`result = denegado`; if the audit write fails it is logged and counted, and the `403` is sent anyway). Permissions come from a per-replica cache keyed by `membership_id + authz_version` (TTL 60 s, at most 50 000 entries, then it stops caching and counts `authz_cache_full_total`). The role resolver is the port `auth.PermissionResolver`; until identity (#29) `serve` wires `auth.DenyAllPermissions`, which denies every route with a permission. An impersonated session never uses a tenant role: its permissions are the grant scope (neither scope ever reaches `identidad.support_access:*`, `identidad.users:*`, `identidad.roles:*`, `identidad.sessions:*` and `empresas.einvoicing:update`; on the rest, `read_only`: only `read`; `full`: every action), and with an unknown scope (the adapter returns none until wave 6) it is denied on every route with a permission. `auth.CheckSite` is the helper a handler calls to answer `403 site_out_of_scope`. `httpx.Extensions.Permission` carries `permission` on `forbidden`, `httpx.PhaseAuthz` is the new log phase, `auth.Routes.Registered()` lists the registered routes, and `NewRoutes` takes the permission resolver and the denial recorder.
- `apps/api`: router/contract parity test (`cmd/wanka/parity_test.go`, #176): every route the real `serve` router registers (`auth.Routes.Registered()`) must match an operation of `apps/api/openapi` in method, path, `x-module` and `x-permission`, and every operation must be registered or listed in `pendingOperations`, which the test requires to be up to date (a pending operation that is already registered, or no longer in the contract, fails).
- `apps/api`: `permission` docs test: a code written without backticks in the two correspondence tables of `resources.md` now fails (it was ignored before).
- `apps/api/openapi`: the contract split per module (#166). `openapi.yaml` is the root (info, security, tags and one `$ref` per path, grouped by module), `paths/<module>.yaml` holds one file per `platform.modules` code (empty ones carry `paths: {}`) and `components/` the shared errors, pagination, money, headers and documents. `docs/architecture/api/openapi.yaml` is removed: there is a single source. The bundle equals the old skeleton except the tags (one `identidad`) and `x-module: none` / `x-permission: none` on the three `/v1/auth/mfa/enrollment/*` routes.
- `apps/api/internal/apigen/<module>`: server generated by oapi-codegen v2.8.2 (strict server, one package per module plus `components`), pinned with the `tool` directive of `go.mod` (runtime v1.8.0); `go generate ./...` rebuilds it and the CI fails on any diff. Routes are never registered with the generated `HandlerWithOptions`: `auth.Routes` registers them (see `apps/api/README.md`, "Servidor generado").

ON CONFLICT DO NOTHING`, `lock_timeout` 3 s for that statement only) and the handler does its effect in that same transaction with `idempotency.InTx`, so the key and the effect commit or abort together. A `2xx` response is stored (exact body plus `Content-Type`, `Location` and `ETag`) and the transaction commits; any other response (`4xx`, `5xx`, a panic, or a failed commit) rolls back and stores nothing, and the response is sent only after the transaction ends. The token is checked before the lock (`401` wins over `429`), and `Idempotency-Key` is rejected under `/v1/auth/*` (`400 malformed_request`) so no failure can be rolled back; tenant creation keeps a mandatory key with its own scope (the staff session in `/platform/v1`, a global key bound to the body hash in self-service signup, #31). An expired, consumed or nonexistent step token is `401 session_expired`, the code #187 fixes. The email is sent through `Mailer` after the commit, without links, and a failed send never fails the login (`emailCodeSent: false`). New `POST /v1/auth/mfa/enrollment/email-code/resend` (3 sends per token, 60 s apart, 10 per user per hour and 20 per 24 h). Enrolling from `/perfil` does not ask for it. No new error `code` (`api/conventions.md` §2, §3, §4, §7 and §8, `api/resources.md`, `api/openapi.yaml`, sequence 01) (#25).
- `docs/architecture/data`: new table `iam.mfa_enrollments` (no RLS, column-level `UPDATE` for `wanka_app`, cleanup by `wanka_worker` 24 h after expiry) with the trigger `iam.guard_mfa_enrollment_writes` (the server sets `created_at` and `email_sent_at`, a consumed token never reopens or changes, sends only go up and the pending secret never rotates), and `iam.users.mfa_failed_attempts`, `mfa_locked_until` and `mfa_lockouts` (`data-model.md` §5 and §6, er-01, and a dated clarification in the ADR 0001 grant matrix); `rls-check` covers its grants, `CHECK`s and trigger (cases E1 and K1c) and adds the mutations `grant_app_update_all_mfa_enrollments`, `revoke_worker_mfa_enrollment_columns`, `drop_mfa_guard_trigger`, `mfa_guard_no_server_created_at` and `mfa_guard_allows_reopen`, all registered in `apps/api/scripts/rls-check.sh` (#25).

- Tenant app (`apps/web`, Next.js 16): 48 mock-backed screens — POS, SUNAT electronic documents (detail, void, credit/debit notes), quotes board and wizard, dispatch guides and reception, customers and clinical record (FDI odontogram, SOAP), appointments, catalog and retail variants, inventory (stock, movements, warehouses, kardex 13.1, physical count), purchases (RCE, suppliers, orders), receivables/payables, cash and Z-reports, RVIE/settlement/management reports, settings (SUNAT, users/roles, audit, integrations, profile), restaurant (floor, kitchen, delivery, reservations) and veterinary (pets, hospitalization, grooming) modules.
- Industry-aware dashboards and navigation (dental, veterinary, restaurant, retail) driven by the selected tenant cookie.
- SaaS admin console (`/admin`): dashboard, tenants, plans, billing, monitoring, staff, support, feature flags, audit, settings, profile and login, with its own indigo theme and a shell shared with the tenant app.
- Standardized UI kit: 40 px controls, `DataTable` with column visibility / density / reset controls, `EntityHeader`, `PageHeader`, `FilterBar`, `SectionNav`, `SectionCard`, `StatCard`, `StatusBadge`/`Tag`, `SearchInput`, `PaginationBar`, `InitialsAvatar`, dynamic state icons; "Andes Teal v2" theme, dark mode, Geist + Geist Mono.
- Test suites: Vitest unit tests and Playwright E2E across desktop / tablet / mobile (no fixed sleeps; overflow checks are polled).
- `Input size="sm"` for dense table rows, `NumberInput` (raw text + `parseNumber`) for typed quantities and prices, and `config/redirects.ts` as the single source for group landings (checked by a unit test).
- Prompts (`prompt/`), design spec and UI standardization audit (`docs/`); `design/` (Stitch exports) is kept local and git-ignored.
