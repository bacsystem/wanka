# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

## [0.15.2] - 2026-11-19

### Added
- `apps/api`: RLS catalog tests (`internal/platform/db/catalog_test.go`) that run on whatever is migrated, with no table listed by hand: tenant tables have `FORCE ROW LEVEL SECURITY` and a `tenant_isolation` whose `USING` and `WITH CHECK` are exactly `tenant_id = app.current_tenant()`; a partition of a tenant table either has no privilege for a runtime role or has its own full RLS; extra policies are in the ADR 0001 whitelist (`FOR SELECT`, or `platform_rw TO wanka_platform`), carry `app.current_tenant() IS NULL` in their user branch and match the ADR text exactly, member state filter included; no `UNIQUE` or primary key of a tenant table skips `tenant_id`; no policy uses `current_setting` without `NULLIF`; every foreign key is indexed and carries `tenant_id` between tenant tables; every `SECURITY DEFINER` function is owned by `wanka_definer`, pins `search_path = pg_catalog, pg_temp` and is closed to `PUBLIC`; no `wanka_*` role has `BYPASSRLS` and only the migrator owns tables. Exceptions live in explicit whitelists (today `iam.sessions` and the four entitlements tables of `platform.*` that carry `tenant_id`: `subscriptions`, `tenant_module_overrides`, `tenant_flag_overrides`, `tenant_usage`, global and without RLS by ADR 0001), each entry citing an ADR that exists in `docs/architecture/adr/`, and a test fails on a stale one. A mutation test applies a throwaway migration that breaks each rule and requires the rule to name the object. `apps/api/README.md` explains how to add an exception (#164).

### Changed
- `apps/api`: the generic checks of `TestCatalogRules` in `iam_session_test.go` moved to the catalog tests (the session-specific ones stay as `TestIAMSessionCatalog`) (#164).

## [0.15.1] - 2026-11-19

### Changed
- `docs/architecture`: a membership that is not `invitado` or `activo` gives no read access to any row of its company, even with no tenant set. `member_read` of `org.tenants` and `own_memberships` of `iam.memberships` now require `status IN ('invitado','activo')`, like the `iam.roles` policy, so «A is not in `GET /v1/me/memberships`» is guaranteed by the database and not by a handler (ADR 0001, clarification). `rls-check` seeds an ex member (suspended) and proves 0 rows with no tenant for him and for a deleted membership, and that an `invitado` and an `activo` member still read theirs; four new mutations (`member_read_tenants_no_status`, `member_read_with_suspended`, `own_memberships_no_status`, `session_lookup_no_restore_deleted`). `member_read` is checked in `pg_policies.qual` against the exact set `{activo, invitado}` (an extra `suspendido` fails too), because `own_memberships` already hides the row from its subquery (#187).
- `docs/architecture`: a failed `POST /v1/auth/refresh` or `POST /platform/v1/auth/refresh` (nonexistent, revoked or expired refresh, or the previous one reused outside the 10 s grace, which also revokes the family) is `401 session_expired`; added to `api/conventions.md` §4, ADR 0004 and sequence 01. The BFF does not retry it and goes to `/login`. The same `401 session_expired` answers a login step token (`challengeToken` or `enrollmentToken`) that is expired, consumed or nonexistent; it gets no `code` of its own because the client action is the same. Every `401` of both planes, from the kernel or from identity (`invalid_credentials` included), carries `WWW-Authenticate: Bearer` without parameters (`api/conventions.md` §2, §3 and §4). `httpx.WriteProblem` now sets the header on every `401` by status, not by a list of codes, so `invalid_credentials` carries it too; the test is `TestWWWAuthenticateOnEvery401AndOnlyOn401` (#187). Compatible (§0): no new `code` (#187).

### Fixed
- `docs/architecture/data/rls-check/05_app.sql`: the «session_lookup does not leak `app.tenant_id`» assertion ran in its own statement, after the transaction setting had been cleared, so it could not tell. The lookup and the check now share one `BEGIN … COMMIT`, and `MUTATION=session_lookup_no_restore` fails in the `wanka_app` step too (#187).

## [0.14.0] - 2026-11-19

### Added
- `apps/api`: entitlements middleware in `auth.Routes`, a step of every `Tenant` route after the two limiters and before the route steps (`NoTenant` and `Public` routes do not go through it). In the order of sequence 08, the first rule that fails wins: a closed company (`readOnly`) with a method other than `GET` or `HEAD` is `403 tenant_read_only` (a closed company is not asked for the subscription); a `morosa`, `suspendida` or `cancelada` subscription is `402 subscription_inactive` on every route, `GET` included, except a fixed list in the code (`GET /v1/exports`, `GET /v1/me/entitlements`); a module outside the enabled list is `403 module_not_enabled` with `module`; `used >= limit` is `403 plan_limit_reached` with `limit` and `used` (a limit key missing from the plan closes; a route that declares `Limit: LimitSites` makes startup fail until sites in use are measured). A company without a subscription (`sin_plan`) has no modules, so it gets `403 module_not_enabled`, not `402`. If the entitlements cannot be read the answer is `503 dependency_unavailable` (or `overloaded`) with `Retry-After: 1` and the request never passes; the log line and the counter of `httpx.WriteDBError` carry `phase=entitlements`, set only in the context of that read (the handler keeps `phase=handler`). The same rules are `Entitlements.Check` and, for the jobs of a company, `Service.CheckJob`: a job does not run for a closed company or a disabled module, and with an inactive subscription only a job that finishes already-issued documents runs (#175).
- `apps/api`: a closed company keeps the modules and flags of its last plan even when its subscription is cancelled, suspended or past due, so its reads do not depend on payment (ADR 0005, «Empresa cerrada»); an open company with a lapsed subscription still has none (#175).
- `apps/api`: `httpx.WriteProblemExt` and the `module`, `limit` and `used` extension members of the problem (`conventions.md` §4) (#175).
- `apps/api`: `wanka serve --plane=tenant` builds `entitlements.Service` over the pool and runs `Service.Run` (the `entitlements_changed` listener) in a goroutine that stops on graceful shutdown, which waits for it like the limiter sweep (#175).

### Changed
- `apps/api`: **breaking for module code, none released yet.** `auth.NewRoutes(rt, resolver, entitlements, options)` takes the entitlements source and `Routes.Handle`/`HandleFunc` take an `auth.Spec{Module, Permission, Limit}` after the class. `Module` and `Permission` are the `x-module` and `x-permission` of the spec; `auth.NoModule` and `auth.NoPermission` (the literal `none`) mean none, and an empty string, a module on a `Public` or `NoTenant` route, `NoModule` on a `Tenant` route outside `GET /v1/exports` and `GET /v1/me/entitlements`, or an unknown limit make startup fail (#175).

## [0.11.0] - 2026-11-19

### Added
- `apps/api`: `money.Amount` (`internal/platform/money`), a `shopspring/decimal` value with a fixed scale that marshals as a decimal string (`"118.00"`, prices and quantities to 4 decimals, exchange rate to 3) and unmarshals only from a plain JSON string (no number, exponent, `+`, leading zeros or negative zero); there is no `float64` anywhere in its API. `pricing.Compute` (`internal/platform/pricing`) is the single pure function that calculates lines, IGV and totals of a voucher for POS, proformas, notes and work orders (prices include IGV; gravado, exonerado, inafecto and gratuito, whose IGV is informative, follows the voucher mode and adds nothing to the total; half-up to 2 decimals per line; unit value computed to 10 decimals and returned to 4; the whole voucher switches to the base × rate mode when the deviation between both modes exceeds 0.50; the global discount is split by group (so line order never matters) and applied to the base and IGV already summed per line, so it never raises the IGV or the total and the total falls by exactly the discount; every amount of the totals must fit `numeric(14,2)`; PEN and USD without ever mixing currencies; `exchange_rate_required`, `totals_mismatch` with field and difference, and `validation_failed` errors). Property tests check `total = subtotal + igv + other - discounts`, 2-decimal amounts, order independence and that a global discount (including 0.01 on carts of many cheap lines) never gives a negative discount nor raises the IGV or the total; 200 lines compute in about 0.3 ms. `testdata/vectors.json` (392 vectors) is the input for the Khipu BETA spike of #56; it is generated by an oracle written only from a prose specification, without reading the Go code, and includes vectors that tell apart the tie order and the free-line rule in `base_rate`. `shopspring/decimal` v1.4.0 is added to `go.mod` and to the `go-arch-lint` rules of the kernel (#167).

## [0.10.1] - 2026-11-19

### Changed
- API contract for the owner's decision on #25 (option a): when login answers `mfa_enrollment_required`, the API emails a one-time `emailCode` and `POST /v1/auth/mfa/enrollment/totp/confirm` requires it next to the TOTP code. The code is 6 digits from the CSPRNG, stored only as an `HMAC-SHA256` keyed with the `enrollmentToken` and compared in constant time; it lives and dies with the token (10 min, a resend does not extend it). A wrong TOTP or `emailCode` counts one failure in the user's second-step counter, shared with `mfa/verify` (`422 validation_failed` per field with `attemptsRemaining`); the fifth one locks the second step for 15 minutes and consumes the user's live step tokens (`429 rate_limited`), and every lock sends an email notice, and the third lock since the last password reset (a correct second step clears the failure count but not the locks) closes the second step until the password is reset; meanwhile login with the right password answers `401 invalid_credentials` like a wrong one (at most 15 failures per password, NIST SP 800-63B §5.2.2). A password reset consumes the step tokens and clears the counters. The token is checked before the lock (`401` wins over `429`), and `Idempotency-Key` is rejected under `/v1/auth/*` (`400 malformed_request`) so no failure can be rolled back; tenant creation keeps a mandatory key with its own scope (the staff session in `/platform/v1`, a global key bound to the body hash in self-service signup, #31). An expired, consumed or nonexistent step token is `401 session_expired`, the code #187 fixes. The email is sent through `Mailer` after the commit, without links, and a failed send never fails the login (`emailCodeSent: false`). New `POST /v1/auth/mfa/enrollment/email-code/resend` (3 sends per token, 60 s apart, 10 per user per hour and 20 per 24 h). Enrolling from `/perfil` does not ask for it. No new error `code` (`api/conventions.md` §2, §3, §4, §7 and §8, `api/resources.md`, `api/openapi.yaml`, sequence 01) (#25).
- `docs/architecture/data`: new table `iam.mfa_enrollments` (no RLS, column-level `UPDATE` for `wanka_app`, cleanup by `wanka_worker` 24 h after expiry) with the trigger `iam.guard_mfa_enrollment_writes` (the server sets `created_at` and `email_sent_at`, a consumed token never reopens or changes, sends only go up and the pending secret never rotates), and `iam.users.mfa_failed_attempts`, `mfa_locked_until` and `mfa_lockouts` (`data-model.md` §5 and §6, er-01, and a dated clarification in the ADR 0001 grant matrix); `rls-check` covers its grants, `CHECK`s and trigger (cases E1 and K1c) and adds the mutations `grant_app_update_all_mfa_enrollments`, `revoke_worker_mfa_enrollment_columns`, `drop_mfa_guard_trigger`, `mfa_guard_no_server_created_at` and `mfa_guard_allows_reopen`, all registered in `apps/api/scripts/rls-check.sh` (#25).

## [0.5.0] - 2026-11-18

### Added
- `apps/api`: HTTP base of the kernel in `internal/platform/httpx`. Every error is RFC 9457 `application/problem+json` with `type`, `title`, `status`, `code` and `requestId`; the HTTP of each `code` comes from one table that a test compares with the 31 codes of `api/conventions.md` §4. `httpx.Router` answers `404 not_found` for undeclared routes and methods (including `OPTIONS`; no `405`, no CORS); a handler that exceeds its 10 s budget answers `503 overloaded` with `Retry-After: 1` after cancelling its context (the transaction rolls back and the connection returns to the pool) and discarding its buffered output; `httpx.Streaming()` routes skip that budget and get a 25 s context from arrival. `httpx.NewServer` disables net/http's own `OPTIONS *` answer and `Router.Handle` rejects subtree patterns (`/x/`, `{p...}`) so no response comes from `ServeMux`. `Content-Length` over 1 MB is `413 payload_too_large` without reading the body, `httpx.DecodeJSON` answers `400 malformed_request`, and a `panic` is `500 internal` without details (#193, #165).
- `apps/api`: in-memory token-bucket rate limiter (implemented as GCRA, exact integer arithmetic) with an injectable key and clock (`httpx.NewLimiter`), `RateLimit-Limit`/`-Remaining`/`-Reset` headers, no token spent by a rejected request across chained limiters, a cap on keys (`503 overloaded`) and `Sweep` of full buckets. Wiring it to session and tenant keys stays in #174 (#193, #165).
- `apps/api`: `internal/platform/clock` (system and fake clocks) and `internal/platform/metrics` (metrics port; the OpenTelemetry adapter comes later); `db.Pool.AcquiredConns` (#193, #165).

### Fixed
- `apps/api`: a lost database connection (SQLSTATE `57P01`-`57P03` or class `08`, or a connection pgx reports closed; never the shape of the error, so a foreign `io.EOF`, a `url.Error` or `conn busy` stay `500`) with the caller's context alive is now `db.ErrUnavailable` and answers `503 dependency_unavailable` instead of `500` when a pool connection dies after a restart or failover; a streaming handler that writes its own RFC 9457 problem after the budget expired now delivers it; the access log marks a connection cut with `http.ErrAbortHandler` as `aborted` (status 0 if nothing was sent) instead of `200`; `httpx.NewServer` sets `MaxHeaderBytes` to 64 KiB; a connection lost during `COMMIT` also carries `db.ErrCommitUncertain` (log `phase=commit`) and every database outage logs one `warn` line and counts `db_unavailable_total` (#193, #165).

### Changed
- `docs/architecture/api/conventions.md` §4: requests that `net/http` rejects before the API chain (invalid escape in the path, garbage request line, bare LF in a header or missing `Host`: `400`; oversized headers: `431`; unsupported `Expect`: `417`; unsupported `Transfer-Encoding`: `501`; unsupported HTTP version: `505`) are answered by Go's server as `text/plain`, a documented exception to the RFC 9457 rule (#193, #165).
- `docs/architecture/api/conventions.md` §3: `RateLimit-*` are not sent on the kernel's `503` for an expired handler deadline nor on the `503` for the limiter's key cap (no bucket to report), nor on the `500` for a `panic`; the deadline and panic responses drop the handler's headers. Clarification only; no behaviour change (#193, #165).
- `apps/api`: `httpx.WriteDBError` answers `db.ErrStatementTimeout` as `503 dependency_unavailable` with `Retry-After: 1` and the generic body, logs one `warn` line (route, phase, module, `sqlstate=57014`, elapsed; no SQL) and counts it by phase and route; with the request context already finished it writes nothing. `httpx.Chain` takes a metrics recorder, `httpx.WriteProblem` takes the `code` and derives the HTTP from the table, and `httpx.NewMux` returns an `httpx.Router` (#193, #165).
- `apps/api/README.md`: `WriteDBError` no longer described as translating everything to `overloaded`; the three database cases and the HTTP base are documented (#193, #165).
